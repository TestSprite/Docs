Your coding agent can read the diff and change your application. The project's TestSprite agent uses requirements, attachments and a test environment to propose changes to the test suite. The CLI connects the two, with a review step before a proposed test becomes part of the suite.

## Check for coverage

Set `PROJECT_ID` to the ID from `testsprite project list`, then list the saved cases.

```bash
testsprite test list --project "$PROJECT_ID"
```

Set `TEST_ID` to the `id` of a likely match and read its steps.

```bash
testsprite test get "$TEST_ID"
```

If the saved case already checks the behavior you changed, run it against a build containing the change.

```bash
testsprite run "$TEST_ID" --env staging --wait
```

To verify the whole suite, use `testsprite run --project <project-id> --env staging --wait`. If the wait times out, [continue waiting with the run ID](/cli/core/running-tests#resuming-a-run).

## Ask for missing coverage

In your Git repository, state an observable expectation. Attach the diff with `--diff` or a specification with `--file <path>`. The project's agent can explore a reachable frontend deployment. For a local-only app, give it the diff or requirements to plan from, then run the saved frontend tests through a tunnel. [Local apps](/cli/core/local-apps).

```bash
testsprite plan "An expired coupon shows an error and leaves the cart total unchanged" \
  --project "$PROJECT_ID" --diff --steps
```

Review the proposed actions and assertions against the requirement. Use `reject` with feedback if the plan needs a change. Once the plan is right, apply it and run the test IDs in `applied.tests`. [Creating tests](/cli/core/creating-tests).

## Diagnose a failure

Set `RESULT_ID` to the failed case's `resultId` from the run's `results[]`. Read the exact result and, if needed, keep the evidence locally.

```bash
testsprite result get "$RESULT_ID" --output json
testsprite result get "$RESULT_ID" --out ".testsprite/results/$RESULT_ID"
```

Compare the expected behavior with the recorded steps or API output. Fix a product defect in the application and rerun the saved test against the updated build. Send an incorrect test expectation back to the project's agent, then review the correction before applying it. [Reading results](/cli/core/reading-results).
