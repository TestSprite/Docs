## The JSON contract

Use `--output json` for scripts. For a launch or `run wait`, `.runs[]` contains execution receipts and `.results[]` contains individual test results. A launch can return a run ID before any result rows exist. Waiting adds count fields in `.summary` and, when needed, execution-level diagnostics in `.runFailures[]`.

| ID | Where to find it | Where to use it |
| --- | --- | --- |
| Test ID | `test list` or `test get` (`id`), result history (`caseKey` when present) | `run <test-id>`, `result list --test <test-id>` |
| Run ID | `run` or `run wait` (`.runs[].runId`) | `run wait`, `run cancel`, `result list --run` |
| Result ID | `run wait` or `result list` (`.results[].resultId`) | `result get <result-id>` |

## Launch once and read a result

This Bash example assumes `PROJECT_ID` names a project with a public default environment. It saves the launch receipt, waits for the run and downloads evidence for each failed, blocked or cancelled result. The script returns the wait's exit code after collecting diagnostics.

```bash
#!/usr/bin/env bash
set -euo pipefail

testsprite run --project "$PROJECT_ID" --output json > launch.json
run_id=$(jq -er '.runs[0].runId' launch.json)

verdict=0
testsprite run wait "$run_id" --timeout 900 --output json > wait.json || verdict=$?

if [[ -s wait.json ]]; then
  jq '{summary, runFailures, partial}' wait.json
  while IFS= read -r result_id; do
    testsprite result get "$result_id" --failed-only \
      --out ".testsprite/results/$result_id" || echo "Evidence incomplete for $result_id" >&2
  done < <(jq -r '.results[] | select(.status == "failed" or .status == "blocked" or .status == "cancelled") | .resultId' wait.json)
fi
exit "$verdict"
```

`run wait` uses lowercase `status` values in `.results[]`. The result reader returns uppercase `testStatus` values and exits 0 when it successfully reads a result, including a failed one. The following commands print result IDs and inspect a selected result.

```bash
set -o pipefail
testsprite result list --run "$RUN_ID" --status failed,blocked,cancelled --output json \
  | jq -r '.results[] | [.resultId, .testStatus, .title] | @tsv'
testsprite result get "$RESULT_ID" --output json \
  | jq '{testStatus, error, cause, fix, failedStep, trace, apiOutput}'
```

## Timeouts and interrupts

An incomplete timeout or interrupt can return `partial: true` alongside the known run receipts and result rows. Use `.runs[].runId` to resume an ordinary run with `testsprite run wait "$RUN_ID"`. Check `runFailures` even when every visible result passed. The execution may still have been cancelled or timed out while waiting for more results. A tunnel the command opened closes on timeout and requests cancellation by default. [Cancelling Runs](/cli/core/cancelling-runs)

A launch can also end before the server confirms all projects. Read `unconfirmedProjects` and reuse `retryIdempotencyKey` with `--idempotency-key` on the complete original command. `notRunProjects` identifies projects the CLI never submitted.

## A minimal CI gate

```bash
testsprite ci run --project "$PROJECT_ID" --env staging --timeout 900 \
  --fail-on-skipped --summary-file testsprite-summary.json \
  --report junit --report-file testsprite-junit.xml
```

`ci run` waits for the verdict and emits reports before exiting. In `testsprite-summary.json`, `.results[]` identifies individual results and `.executionReport.runId` identifies the execution when the report is available. With `ci run --output json` the same summary is under `.summary`. See [CI/CD](/cli/integrations/ci-cd).

## Debugging a script

`--verbose` logs retry and polling activity to stderr. `--debug` adds HTTP method, path, request ID and latency. JSON errors also go to stderr. Keep stdout and stderr separate when passing data to `jq`.

Preview a public launch without submitting it:

```bash
testsprite run --project "$PROJECT_ID" --target-url https://staging.example.com \
  --dry-run --output json
```

A dry-run launch can return empty ID arrays and the requests it would make. An authenticated launch preview without an explicit target may read saved environment metadata. For sample result data without credentials, use `testsprite result get example --dry-run --output json`.
