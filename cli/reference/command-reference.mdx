Use `testsprite --help` to list commands and `testsprite <command> --help` for the options and examples for one command.

## Global flags

| Flag | Purpose |
| --- | --- |
| `--output <mode>` | Choose `text` (default) or `json` for scripts. |
| `--profile <name>` | Select a profile from `~/.testsprite/credentials` (default `default`). |
| `--verbose`, `--debug` | Log retries and polling, or HTTP diagnostics, to stderr. |
| `--dry-run` | Preview the command. A launch with credentials and no explicit target may read the saved environment to check for a tunnel. It starts no run. |
| `--request-timeout <seconds>` | Limit each HTTP request (1–600 seconds, default 120). |
| `-V, --version`, `-h, --help` | Print the version or help. |

## Setup and account

| Command | Purpose |
| --- | --- |
| `setup` | Validate and save an API key, install skills for detected agents and add `.testsprite/` to the project's `.gitignore`. Use `--from-env --yes` for unattended setup, `--agent <target>` for one agent, `--no-agent` to skip skills, or `--no-gitignore` to skip the ignore entry. |
| `doctor` | Check the runtime, credentials, API connection, workspace, tunnel permission, skill installation and Git ignore configuration. Failed checks exit 1. |
| `auth status`, `auth remove` | Inspect the active key, workspace and scopes, or remove the profile's saved credentials. |
| `usage` (alias `credits`) | Show the workspace plan and organization wallet. |
| `completion [bash\|zsh\|fish]` | Print completions for a shell. |

## Projects and environments

Create the project first, then give it an environment. The first environment becomes the default. In the examples, set `PROJECT_ID` to the ID printed by `project create`.

```bash
testsprite project create --type frontend --name "Storefront"
testsprite project env create "$PROJECT_ID" --name staging --url https://staging.example.com
testsprite project env list "$PROJECT_ID"
testsprite project env get "$PROJECT_ID" staging
```

- `project list` and `project get <id>` show project metadata. `project update` accepts a name, agent instructions and frontend locator preferences. Use `project delete <id> --confirm` to permanently remove a project.
- `project env create` takes `--url` or, for a local frontend, `--local <port>`. On a frontend environment set `--sign-in public|account|otp|manual`; use `--username` and `--password-file` for a test account. Change an existing environment's sign-in mode in the Portal.
- `project env update <project-id> <name>` can change the URL, account credentials, variables or name. `--var KEY=VALUE` sets a non-secret value. Use `project env set-default <project-id> <name>` to switch the default and `project env delete <project-id> <name> --confirm` to remove an environment.
- On a backend environment, `create` and `update` accept `--auth none|bearer|basic|apikey`, `--credential-file <path>`, repeatable `--header "Name: value"`, `--header-file <path>`, or `--auto-auth-file <path>` for a sign-in that refreshes the credential. Reads redact secrets.

See [Environments](/cli/core/environments) for sign-in examples.

## Plan and review tests

| Command | Purpose |
| --- | --- |
| `plan "<request>"` | Ask the project's agent to add, change or remove tests. `--project` selects a project, `--file` attaches a document and `--diff [base]` attaches a Git diff. The agent works on the project's default environment unless the request names another. |
| `status` | Inspect the conversation. Use `--list` to find a conversation, `--wait` to follow it, or `--steps` to see proposed steps. |
| `reply "<message>"` | Answer a chat message or refine the request when no card is pending. |
| `apply` | Approve the pending action shown on the card. Use `--only` or `--exclude` with comma-separated test references for a plan, `--secret-stdin` for a card requesting a secret, or `--answer <n>=<choice>` for a question card. A run card starts a run; `--env <name>` starts it on another environment. |
| `reject "<reason>"` | Decline the pending proposal and explain what to change. |
| `stop`, `discard` | Stop the agent's current work, or drop its task and release pending proposals. |

Follow-up commands use the conversation last selected in this folder. Pass `--project <id> --conversation <id>` to select it explicitly and `--card <id>` on `apply` or `reject` to identify the proposal. Use `--no-wait` on `plan`, `reply`, `apply` or `reject` to return immediately and `status --wait` to follow progress later.

## Test definitions

```bash
testsprite test list --project "$PROJECT_ID" --type frontend
testsprite test get "$TEST_ID" --output json
```

`test list` follows all pages by default. Use `--max-items <n>` to cap the total, or `--page-size <n>` (1–100) and `--starting-token <token>` to fetch one page at a time. Cases have an `id`, `slug`, `title`, `type`, version and step count. Read the latest outcome with `result list --test <test-id> --limit 1`. Inspect generated code in the Portal.

## Launch, wait and cancel

| Selection | Command |
| --- | --- |
| Entire project | `testsprite run --project <project-id> --wait` |
| Tests with “checkout” in their name | `testsprite run --project <project-id> --filter checkout --wait` |
| One or more named tests | `testsprite run <test-id> [more-test-ids...] --wait` |
| All cases in a saved list | `testsprite run --testlist <list-id> --wait` |
| Selected cases in a saved list | `testsprite run <test-id> [more-test-ids...] --testlist <list-id> --wait` |

A project selector excludes positional test IDs and list selection. With no selector, `run` reads `TESTSPRITE_PROJECT_ID`. Named tests are grouped into one run per project, with up to 5,000 selected IDs per project. List runs use their saved project/environment bindings.

| Launch option | Behavior |
| --- | --- |
| `--env <name>` | Use this environment's URL and settings for a project or named tests. The default is the project's default environment. |
| `--target-url <url>` | Frontend tests can run against a public URL or a loopback HTTP origin. The CLI uses the environment for that origin, or a temporary environment removed after the run. With `--env`, it uses the named environment's settings. A sign-in bound to a different origin can return `frontend-auth-target-origin-mismatch` (exit 6). |
| `--local <port>`, `--tunnel-client <id>` | Reach a frontend on this machine through an automatic tunnel or attach to a running tunnel. `--local` implies waiting. `--no-wait` refuses a launch needing an automatic tunnel. |
| `--local-host <host>`, `--skip-preflight` | Select a loopback host with `--local` (`localhost`, `127.0.0.1` or `::1`), or skip the pre-charge reachability probe when the machine running the CLI cannot make a representative check. |
| `--no-cancel-on-interrupt` | Leave unfinished work running when a tunnel owned by a project/named invocation closes. Steps needing that tunnel can then fail. |
| `--allow-empty` | Accept zero dispatched tests for a project or multi-ID batch. The default is exit 5. |
| `--wait`, `--timeout <s>` | Wait for the execution, including later integration results. One deadline covers all executions (1–3600 seconds). Default 600 seconds, or 1200 for a project/named launch through a tunnel. Lists default to 600 in either case. |
| `--max-concurrency <n>` | Limit server dispatch per execution. Project/multiple IDs use 1–100, default 50 (tunnel 1–15, default 5). A single named test defaults to 5. Lists use 1–50, default 10 (tunnel 1–10, default 5). |
| `--skip-dependencies` | Skip prerequisites for a backend test. List selection uses its own saved settings and rejects this flag. |
| `--idempotency-key <key>` | Retry the same launch with the same request key. An unconfirmed project launch provides a `retryIdempotencyKey` to replay the whole command. |
| `--report junit --report-file <path>`, `--summary-file <path>`, `--gh-output` | Write JUnit, a JSON summary with `results[]`, or GitHub annotations and a job summary for a waited batch. |

`run` prints executions in `runs[]` and individual results in `results[]`. A launch can return before any result rows exist. A blocked, failed or cancelled result can be inspected by its `resultId`. To resume or cancel, use the execution's `runId`.

```bash
testsprite run wait "$RUN_ID" --timeout 900
testsprite run cancel "$RUN_ID"
```

Both commands accept several run IDs. Waiting uses one shared deadline (default 600 seconds). Cancellation covers queued work and later phases and returns per-result cancellation and refund outcomes. An already-finished or already-cancelled execution returns its current state. See [Cancelling Runs](/cli/core/cancelling-runs).

## Results and evidence

```bash
testsprite result list --run "$RUN_ID" --status failed,blocked,cancelled
testsprite result list --test "$TEST_ID" --env staging --limit 1
testsprite result get "$RESULT_ID" --output json
testsprite result get "$RESULT_ID" --out ".testsprite/results/$RESULT_ID" --failed-only
```

- `result list` requires exactly one of `--run` or `--test`. Both accept `--status` with `passed`, `failed`, `running`, `blocked` or `cancelled`. Include `cancelled` explicitly to see cancelled results. Test history is newest first and accepts `--env` and `--limit` (1–100, default 20).
- `result get` takes a **result ID**. Its JSON includes the error, cause, suggested fix, steps, failed step, video and any backend traceback and captured output. A successful read exits 0 for any verdict.
- `--out` creates the directory and writes `result.json` and available evidence, including `steps/` and sign-in evidence where available. `--failed-only` keeps failed steps and one neighbor on each side, or all steps if none failed. A partial download exits 10. See [Reading Results](/cli/core/reading-results).

## Test lists and schedules

`testlist create --name <name>` creates a list. Use `add` or `remove` with the list ID and test IDs to change its members. Bind environments with repeatable `--project-env <project-id>:<name>` on `create` or `update`. `testlist list` and `testlist get` expose `lastRunId` and `lastRunCreated` when available. Deleting a list with `--confirm` also deletes its schedules.

`schedule create` takes `--name`, `--cron`, `--target-type project|testList` and `--target-id`. A five-field cron uses UTC unless you set `--timezone`. A project schedule inherits the project's default or can be pinned with `--env`. A list schedule uses the list's bindings. Use `schedule list`, `schedule get` or `schedule update --pause` / `--resume` to manage it. View past schedule executions in the Portal. See [Test Lists & Schedules](/cli/integrations/test-lists-and-schedules).

## CI

- `ci init github` generates a GitHub Actions workflow. Select the project and saved environment with `--project` and `--env`. Use `--path` to choose the workflow filename. `--set-secret` writes or replaces the API key secret via `gh` in the chosen repository.
- `ci run` selects a project, always waits, and gates on the verdict. Use `--target-url` for a preview URL or `--wait-for-status` and `--target-url-template` for a preview announced by a check. `--fail-on-skipped` fails the check for skipped tests. `--summary-file` writes the CI summary, and `--report junit --report-file <path>` adds JUnit XML. See [CI/CD](/cli/integrations/ci-cd).

## Coding agents and tunnels

- `agent list` shows available targets and skills. `agent install [targets...]` writes guidance for your coding agent, and `agent status` checks the installed guidance. Refresh a stale target with `agent install <target> --force`. See [Coding Agent Integration](/cli/core/agent-integration).
- `tunnel start` opens a foreground tunnel. Use its client ID with `run --local <port> --tunnel-client <id>` and a project or test selector. `tunnel list` shows active bindings, `tunnel status <client-id>` checks one and `tunnel stop <client-id>` revokes it. `tunnel stop --all --confirm` revokes all your bindings, including those used by other jobs. See [Local Apps](/cli/core/local-apps).
