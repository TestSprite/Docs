---
title: "Coding Agent Integration"
description: "Install and refresh the TestSprite skills your coding agent uses to verify changes."
---

The TestSprite CLI installs instructions into your repository for your coding agent. The coding agent uses the CLI to run saved tests, inspect results and fix your product code. When coverage needs to change, it asks the project's TestSprite agent for a proposal that you can review and apply.

## Install the skills

Run `testsprite setup` in the root of your repository to connect a workspace and install the skills. To choose one coding agent explicitly, run `testsprite setup --agent codex`. After setup, you can add targets locally.

```bash
testsprite agent install cursor codex
testsprite agent status
```

| Skill | When to use it |
| --- | --- |
| `testsprite-onboard` | Seed an empty project. Identify key flows, request a first suite, review the plan and smoke-test a few saved cases. |
| `testsprite-verify` | Check a feature or fix. Run covering tests, review missing coverage with the project's agent and inspect any failing result. |
| `testsprite-ci` | Set up a pull-request check for a preview deployment. [CI/CD integration](/cli/integrations/ci-cd). |

By default, `agent install` installs all three skills. Use `--skill testsprite-verify` to install only the verification workflow or `--dir <path>` to choose the repository. The install command works offline.

## Supported agents

| Target | Where instructions are installed |
| --- | --- |
| `claude` | `.claude/skills/{skill}/SKILL.md` |
| `antigravity` | `.agents/skills/{skill}/SKILL.md` |
| `cursor` | `.cursor/rules/{skill}.mdc` |
| `cline` | `.clinerules/{skill}.md` |
| `kiro` | `.kiro/skills/{skill}/SKILL.md` |
| `windsurf` | `.windsurf/rules/{skill}.md` |
| `copilot` | `.github/instructions/{skill}.instructions.md` |
| `codex` | A managed section of `AGENTS.md` |

`testsprite agent list` lists the targets supported by your CLI version. `testsprite agent status` shows what is installed in the current repository.

## Checking skill health

After upgrading the CLI, run `testsprite agent status`. Older installations may still instruct your coding agent to use commands from a previous version.

| State | Meaning |
| --- | --- |
| `ok` | Matches the installed CLI's skill content |
| `absent` | Skill is missing for that target |
| `stale` | Installed content was generated from an older skill body |
| `modified` | The current skill was edited locally |
| `unmarked` | The file has no recognized installation marker |
| `corrupt` | The Codex managed section has malformed markers |

For a stale standalone file, reinstall the affected target with `--force` to keep a backup. For Codex, reinstall to refresh the managed section. Review local modifications before replacing them.

```bash
testsprite agent install cursor --force
testsprite agent install codex
testsprite agent status
```

Status exits `1` if any installed skill is stale, modified, unmarked or corrupt. If a Codex section is corrupt, repair its markers before reinstalling.

## Give the agent a verification task

> Verify the guest checkout change against staging. Use the existing checkout test if it covers the change. If coverage is missing, show me the proposed assertions before applying them. Report the verdict and the result ID for any failure.

For existing coverage, the agent can run `testsprite run <test-id> --env staging --wait --output json` and inspect a failure with `testsprite result get <result-id>`. For new coverage it can call `testsprite plan` with the diff, inspect the proposed steps and run the saved test IDs after `testsprite apply`. [The agent loop](/cli/concepts/the-agent-loop).

In an automated workflow with several conversations, set `PROJECT_ID`, `CONVERSATION_ID` and `PROPOSAL_ID` to the reviewed plan's `projectId`, conversation `id` and `proposal.id`. Pass those values explicitly to apply that proposal.

```bash
testsprite apply --project "$PROJECT_ID" --conversation "$CONVERSATION_ID" --card "$PROPOSAL_ID" --output json
```
