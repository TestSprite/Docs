---
title: "Running Tests Again"
description: "Repeat saved cases after a fix, select the cases that failed, or request strict replay of stored test code."
---

## Repeat a saved test

After deploying a fix, start a new execution with the same **test ID** and environment. The new execution gets a new `runId` and produces a new `resultId` for the case.

```bash
testsprite run "$TEST_ID" --env staging --wait
testsprite result list --test "$TEST_ID" --env staging --limit 2
```

If you only want to see how an existing execution finished, use `testsprite run wait "$RUN_ID"`. It resumes waiting for that execution without launching another.

## Repeat failed cases from a run

List the previous execution's failed or blocked results. In each row, `resultId` opens the evidence and `caseKey` identifies the saved test.

```bash
testsprite result list --run "$RUN_ID" --status failed,blocked --output json
```

After reviewing the failures, copy the `caseKey` values you want into a new launch. Set the same environment and target to compare like with like. For a list's selected members, reuse its saved environment mappings with `--testlist`.

```bash
testsprite run "$TEST_ID_A" "$TEST_ID_B" --env staging --wait
```

A backend run can include dependent work such as fixture setup and cleanup. Use `--skip-dependencies` on the named backend cases only when the required state already exists.

## Auto-heal and strict replay

On supported frontend runs, the server can repair stale generated test code when the UI changes and save the revised code. For a regression check that must exercise the existing stored code, request strict replay on a hosted target.

```bash
testsprite run "$TEST_ID" --env staging --no-auto-heal --wait
```

Check the CLI output for an advisory if the server could not honor strict replay. Availability depends on the workspace and whether the case has replayable code. If the server reports `no_stored_code`, run the case once without the flag to generate code. Frontend runs through a local tunnel use the agent execution path. You can inspect generated code in the Portal. [Testing Local Apps](/cli/core/local-apps)

If the expected behavior itself changed, request a revision through the project's agent so you can review the new assertion. [Editing and Deleting Tests](/cli/core/editing-tests)
