title: "Environments"
description: "Choose where a project runs and how its frontend or API tests sign in."
---

An environment gives a target a name, such as `staging`, and stores its URL and sign-in settings. The first environment you create becomes the project default. A command that selects a named environment uses that name within the project.

## Manage environments

```bash
testsprite project env create "$PROJECT_ID" --name staging --url https://staging.example.com
testsprite project env list "$PROJECT_ID"
testsprite project env get "$PROJECT_ID" staging
testsprite project env update "$PROJECT_ID" staging --url https://new-staging.example.com
```

Creation requires exactly one target, `--url` or `--local <port>`. Remote targets must be publicly reachable HTTP(S) URLs. Local environments are for frontend apps. To change the default, run `testsprite project env set-default "$PROJECT_ID" staging`. To delete another environment, use `project env delete` with the name and `--confirm`. The default must be reassigned before deletion. [Testing Local Apps](/cli/core/local-apps)

## Sign-in modes

For a frontend environment, set `--sign-in` at creation. Open the existing environment in the Portal to change its sign-in mode or capture a manual browser session. `project env get` shows the current settings.

| Mode | How the browser signs in |
| :--- | :--- |
| `public` | Opens the app without signing in. |
| `account` | Uses the environment's test username and password. |
| `otp` | Uses TestSprite's provisioned email or SMS channel. Choose the channel at creation with `--otp-channel`. |
| `manual` | Reuses a session you capture in the Portal, for example for an SSO login. |

```bash
testsprite project env create "$PROJECT_ID" --name qa --url https://qa.example.com \
  --sign-in account --username tester@example.com --password-file ./qa-password.txt
testsprite project env update "$PROJECT_ID" qa --username tester@example.com --password-file ./new-password.txt
```

`--clear-credentials` clears the stored account. Local environments support `public` and `account`. For plain-text frontend settings, `--var REGION=west` on create or update sets a variable. Its value is visible in `project env get`.

## Backend API authentication

A backend environment stores the API base URL, credentials, and headers. A backend test that uses the environment URL picks up this setting. A URL written into the code stays as written.

```bash
testsprite project env update "$PROJECT_ID" staging --auth bearer --credential-file ./qa-token.txt
testsprite project env get "$PROJECT_ID" staging
```

- `--auth` accepts `none`, `bearer`, `basic`, or `apikey`. Use a credential file to keep the value out of shell history. Selecting `none` clears the stored credential.
- `--header` and `--header-file` replace the set of extra headers sent with every request. Use one `Name: value` per line in a file for headers containing secrets.
- For a sign-in that refreshes the credential, use `--auto-auth-file ./login.json`. The server validates the settings and tries the sign-in. `project env get` shows whether secrets are set and any sign-in error. Saving advanced settings depends on your workspace plan.

## Choose an environment for a run

```bash
testsprite run --project "$PROJECT_ID" --env staging --wait
testsprite result list --test "$TEST_ID" --env staging --limit 1
```

`--env` selects the target for a named test or a project run. Saved test lists instead use their stored environment mappings. A planning conversation works on the project's default environment unless your request names another. When the agent proposes a run, `apply --env <name>` starts it on a different environment.

### Ad-hoc targets and temporary environments

For a frontend preview, `--target-url` supplies a URL for one run. Without `--env`, TestSprite reuses an environment at the same origin or creates a temporary environment that takes its sign-in settings from the default. Temporary environments are hidden from the project's list and are removed after the run. With `--env`, the selected environment supplies the settings. A recorded session, OTP, or login-once setup can require the original origin. [Running Tests](/cli/core/running-tests#run-against-a-url-without-creating-an-environment)
