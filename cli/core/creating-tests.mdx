---
title: "Creating Tests"
description: "Ask your project's agent for tests, review the proposed steps, and run the cases you save."
---

Start with a behavior someone can observe. For example, a declined card should leave the cart intact and show the shopper why payment failed. The project's agent can use that expectation to propose test cases. The same conversation is available in the Portal.

## Ask for frontend or API tests

For a deployed web app, the hosted agent works on the project's default [environment](/cli/core/environments), with its URL and sign-in. To use another environment, name it in your request. The agent says which one it used.

```bash
testsprite plan "Check that a declined card keeps the cart intact and shows the payment error" \
  --project "$PROJECT_ID" --steps
```

For a backend project, attach the API specification and describe the responses you expect. Replace the example path with your spec.

```bash
testsprite plan "Cover order creation and rejection of a missing product ID" \
  --project "$PROJECT_ID" --file ./openapi.yaml --steps
```

`--file` is repeatable for requirements, tickets, or API specs. From a Git checkout, `--diff` attaches your change. For a local-only app, the hosted agent works from that material. You can run its saved frontend cases against your machine through a tunnel. [Testing Local Apps](/cli/core/local-apps)

## Review the proposal

`plan` normally follows the conversation until the agent replies or needs a decision. To leave it working, add `--no-wait`. Return from the same folder to see the proposed additions, changes, removals, and steps.

```bash
testsprite status --wait --steps
```

If the agent asks a question in a chat message, answer with `testsprite reply "your answer"`. For a question card, answer each question by its number, for example `testsprite apply --answer 1=b --answer 2=a,c`, or your own words in quotes. You can also answer it in the portal. Review the proposed actions and expected outcomes. To request a change, explain what the agent should revise.

```bash
testsprite reject "Also check that the cart still contains the original items" --steps
```

## Save the reviewed tests

When the pending card proposes the test changes you want, apply it. To approve a specific card, pass its ID to `--card`. A **run** card starts an execution when applied, so check the card's action before you confirm.

```bash
testsprite apply --output json
```

For a test plan, `applied.tests` contains the saved test IDs. You can also accept a subset with `--only` or `--exclude`, using the references shown in the proposal. If you have several conversations open, `status --list --project "$PROJECT_ID"` shows their IDs. Pass `--conversation` to target the right one.

## Run the saved cases

Use a saved test ID to try one case, or run the project. The wait command's exit status tells you whether the execution passed. [Running Tests](/cli/core/running-tests)

```bash
testsprite test list --project "$PROJECT_ID"
testsprite run --project "$PROJECT_ID" --env staging --wait
```
