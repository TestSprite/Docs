---
title: "Cancelling a Run"
description: "Stop a whole execution, check cancellation and refund outcomes, or detach and resume waiting later."
---

## Stopping a run

Use the `runId` from the launch receipt. Cancellation covers the entire execution, including queued tests and later integration work. You can supply multiple run IDs.

```bash
testsprite run cancel "$RUN_ID" --output json
```

Each entry in `runs[]` records the execution ID, `alreadyCancelled`, `alreadyFinished`, and the individual result outcomes. Finished results keep their verdict. When a result includes a `refund`, check its `status` for `refunded`, `not_charged`, or `failed`. A failed refund can be retried by cancelling the same run again.

An already-finished or already-cancelled execution is a successful cancellation response. With several IDs, the CLI reports which requests succeeded and names errors separately. For example, an unknown run ID can produce exit `4` even if another cancellation succeeded.

## Ctrl-C detaches

Ctrl-C during an ordinary `--wait` stops the CLI and leaves the cloud execution running and billable. A wait timeout also leaves that execution running. Resume from any terminal with the same workspace credentials, or cancel it explicitly.

```bash
testsprite run wait "$RUN_ID" --timeout 900
```

`run wait` returns exit `1` for a cancelled execution, including when its earlier test results all passed. To list cancelled result rows, include `cancelled` in the status filter.

```bash
testsprite result list --run "$RUN_ID" --status cancelled
```

## Runs through a tunnel

When this invocation opened a tunnel, Ctrl-C or a timeout normally requests cancellation of its unfinished executions before it closes the tunnel. Check the printed cleanup result. If cancellation could not be confirmed, `run cancel` can retry it. `run wait` cannot reopen a closed tunnel.

`--no-cancel-on-interrupt` opts out of that cancellation. The unfinished execution remains billable and loses access to the app once its tunnel closes. If you borrow a tunnel with `--tunnel-client`, its owner keeps it open when you interrupt the waiting command. [Testing Local Apps](/cli/core/local-apps)
