## What Step-by-Step Shows

The **Steps** panel in the left column of the test detail page lists every action and assertion from the run. A **Test Result** block at the top shows the outcome (PASSED / FAILED / BLOCKED / RUNNING). Click a step to load the **HTML snapshot** of the page at that moment in the right pane.

<Frame>
  <img src="../../../images/ui-testing-step-step-show.png" alt="A step row selected in the list, loading that moment’s HTML snapshot in the right pane" />
</Frame>

| Element | What it shows |
| :--- | :--- |
| <kbd>Step number</kbd> | Order in the run (1, 2, 3…) |
| <kbd>Action / Assertion</kbd> | The kind of step: `click`, `fill`, `navigate`, `scroll`, `wait` for actions; `visible`, `text`, `url`, `enabled` for assertions |
| <kbd>Description</kbd> | Plain-English summary of what the step did or checked |
| <kbd>Status</kbd> | Green (passed), red (failed), neutral (no assertion) |

## Where to Find It

Click any UI test in the project's test list to open its detail page (see [Test Detail](/web-portal/core/working-with-test/test-detail)); the **Steps** section is in the left column. Tests run from a schedule show the same view in the schedule run's per-test detail.

<Frame>
  <img src="../../../images/ui-testing-step-find.png" alt="The Steps section inside a test detail page, with the Test Result block above step 1" />
</Frame>

<Info>
**The Steps section always shows the most recent run** of that test. To look at an older run, open it from <kbd>Test Runs</kbd>.
</Info>

## The Video and the Snapshot

The right pane has a **Preview** tab with the full recorded video and a **Code** tab with the test code. Clicking a step swaps the pane to that step's HTML snapshot; click the **Test Result** block to return to the video. Use the video for a continuous run-through and the snapshots to pin down a single action.

## Failure Localization

The failed step is highlighted in the list. Click it to load its snapshot, then read the failure detail panel below.

<Frame>
  <img src="../../../images/ui-step-error-panel.png" alt="Step-by-step view of a completed UI test" />
</Frame>

A UI test's failure detail has three tabs; read them in order:

| Tab | What you see |
| :--- | :--- |
| <kbd>Error</kbd> | *What* went wrong: the failed assertion, or why the AI judge marked the run as not passing. Common problems, such as UI drift or a failed sign-in, get a plain-English headline; other errors show the raw message. |
| <kbd>Cause</kbd> | *Why* it went wrong: an AI diagnosis one level deeper than the raw error. |
| <kbd>Fix</kbd> | *What to do*: an AI-authored suggestion, marked as AI-generated. It's read-only guidance you apply yourself. |

<Note>
UI tests show **Error / Cause / Fix** only. The **Trace** tab (a raw stack trace) appears for backend tests, which also show the response output for API calls.
</Note>

## Getting a Fix You Can Paste Into Your IDE

When you want to hand a fix straight to a coding agent (Claude Code, Cursor, or any LLM agent pointed at your codebase), use a **copyable fix prompt**: a repo-oriented prompt listing each problem found and what to change. For one failing test, click **Copy fix prompt** in the failure panel on this page. For the whole run or several failures:

## When the Steps Look Fine but the Test Failed

Occasionally every step passes but the test fails. The usual causes:

| Cause | What it looks like |
| :--- | :--- |
| <kbd>Final assertion outside the step list</kbd> | Code asserts after the main flow, so the failing assertion isn't tied to a step row |
| <kbd>Hidden timeout</kbd> | The run took too long overall, even though no single step did |
| <kbd>Post-run validation</kbd> | A check after the main flow caught something the in-flight asserts missed |

The **Error / Cause / Fix** tabs below the Preview/Code area show the error that isn't tied to a step.

## Fixing the Test Itself

When a step is wrong (a bad description, a missing action, an assertion that doesn't match your intent), rewrite the steps and re-run in one go with [Edit Steps & Rerun](/web-portal/core/ui/ui-rerun#edit-steps--rerun). To refine a test conversationally instead, see [Managing Test Cases](/web-portal/core/working-with-test/managing-test-cases).

## Edge Cases & Troubleshooting

<AccordionGroup>
  <Accordion title="The Steps section is empty for a test that ran">
    It shows "Collecting steps…" while the run is in progress and "No steps recorded for this test run." if the run produced no step records. Refresh once the status flips to Passed/Failed.
  </Accordion>
  <Accordion title="A step's HTML snapshot shows a blank page or a loading spinner">
    The snapshot was captured before the page settled, which is common on very fast or animation-heavy pages. The next step's snapshot usually shows the settled state.
  </Accordion>
  <Accordion title="The video is missing but the steps are there">
    Recording failed for this run. The steps and snapshots still show what happened.
  </Accordion>
  <Accordion title="The steps show actions I didn't write into the test">
    Auto-Heal ran and recovered, so the list shows what actually executed rather than the saved script. The saved test stays untouched unless you explicitly save updates. See [Auto-Heal](/web-portal/core/ui/auto-heal).
  </Accordion>
</AccordionGroup>
